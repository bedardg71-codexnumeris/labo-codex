## Méthodologie

Script d'audit en lecture seule, exécuté dans la console Safari sur l'instance principale. Parcours récursif de chaque item de bibliothèque. Pour chaque chaîne textuelle rencontrée, test contre 13 patterns suspects connus (XSS classiques, URIs javascript/vbscript/data:html, CSS expression, attribut srcdoc). Champs ignorés pour éviter les faux positifs en masse : `imageBase64`, `thumbnail`, `thumb`, `blob`, `fichierBase64` — le risque polyglotte image+JS est traité par Défense O, hors périmètre de cet audit textuel.

### Note sur `bibliothequeTampons` absente

Aucun tampon n'a été versé dans la bibliothèque partagée à ce jour. Les autocollants utilisés vivent ailleurs (built-ins + clé `tamponsPersonnalises`). C'est conforme à l'usage actuel — pas un signal d'anomalie.

## Conclusion

Les bibliothèques partagées et les cartouches actifs sont **sains à l'instant T** pour les patterns testés. Aucun payload XSS connu n'y dort.

Cet état constitue la **baseline du 6 mai 2026** : tout résultat ultérieur de ce script qui s'écarterait (apparition d'une trouvaille) serait un signal d'incident à investiguer.

## Limites

- Audit textuel uniquement : ne couvre pas les payloads cachés dans les blobs base64 (polyglottes image+JS — voir Défense O).
- 13 patterns connus : un payload sophistiqué utilisant un vecteur non listé (par exemple, encodage Unicode équivalent à `..`, balise HTML5 récente avec handler) passerait au travers.
- Instant T : aucune garantie sur les sessions futures avant que les défenses Phase 0 (notamment Défense B) ne soient en place.

## Cadence recommandée

- À chaque ajout d'un nouveau type d'objet partagé.
- Avant et après chaque session de partage de bibliothèques avec un collègue.
- Trimestriel par défaut.
- Toujours après un import depuis un canal externe (ZIP venu d'un tiers).
