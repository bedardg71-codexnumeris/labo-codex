1. La page est un arbre

Une page n'est pas une suite de lignes : c'est un emboîtement. Des boîtes dans des boîtes. Le retrait à gauche n'est pas de la décoration, il dit qui contient qui.

<div class="carte accordeon">
    <div class="accordeon-header">
        <h3 class="carte-titre-bleu">
            <span class="accordeon-chevron">▼</span> Micro-données ACP
        </h3>
    </div>
</div>

Quatre niveaux : une carte, qui contient un en-tête, qui contient un titre, qui contient le petit chevron. C'est le squelette de l'accordéon « Micro-données ACP » de tes Préférences.

Analogie
Ton plan de cours : partie, section, sous-section. La mise en retrait est le sens. Si tu déplaces un paragraphe d'un niveau, tu ne l'as pas juste bougé : tu l'as fait changer de propriétaire.
Ce que ça t'achète
Quand quelque chose s'affiche au mauvais endroit à l'écran, la première question n'est pas « quelle ligne est fautive ? » mais « dans quelle boîte cette chose est-elle tombée ? »

2. La balise : ouvrir, contenir, fermer

<h3>Micro-données ACP</h3>

Trois choses, pas plus : une marque d'ouverture, le contenu, une marque de fermeture identique avec une barre oblique. Le contenu est encadré, comme entre des guillemets ouvrants et fermants.

La balise dit ce que la chose est, pas de quoi elle a l'air.

h3 veut dire « titre de troisième niveau ». Pas « gros texte bleu ». Qu'il soit bleu, blanc ou minuscule ne le regarde pas : ça, c'est l'affaire du CSS.

BaliseCe qu'elle dit
h1 à h6un titre, du plus important au moins important
pun paragraphe
buttonun bouton, une chose sur laquelle on agit
inputun champ à remplir ou à cocher
labell'étiquette qui accompagne un champ
spanun bout de texte qu'on isole, sans lui donner de sens particulier
divla boîte neutre : regrouper, sans rien dire de plus
Pourquoi tant de div
Parce que div ne veut rien dire, justement. C'est la boîte qu'on prend quand on a seulement besoin de regrouper. Une page bien écrite préfère la balise qui dit quelque chose quand il en existe une : button plutôt que div cliquable, parce qu'un lecteur d'écran, lui, entendra la différence.
Deux exceptions à connaître
Certaines balises n'ont rien à contenir et ne se ferment donc pas : <input>, <img>. Et <!-- ceci est un commentaire --> est du texte écrit pour les humains : le navigateur l'ignore complètement.

3. L'attribut : la précision collée à la balise

Un attribut se loge à l'intérieur de la marque d'ouverture, sous la forme nom="valeur". Il précise, il ne contient rien.

<img src="icons/icon-book.svg" alt="" class="btn-inline-icon">

Trois attributs ici : src dit quel fichier d'image afficher, alt donne le texte de remplacement (vide ici parce que l'icône est décorative), class pose une étiquette – on y arrive.

Analogie
L'annotation en marge d'une consigne. La consigne reste la consigne ; l'annotation la précise.

Les attributs que tu croiseras le plus dans ton app : id (un nom unique pour un élément précis, comme id="accordeon-acc-acp"), type (la sorte de champ : texte, case à cocher), checked (la case est cochée au départ), title (l'infobulle au survol).

4. La classe : l'étiquette qui relie tout ★

C'est le point de bascule du cours. Tout le reste en découle.

<div class="carte accordeon">

Cette boîte porte deux étiquettes : carte et accordeon. Elles sont séparées par une espace, et l'ordre n'a aucune importance.

Une classe ne fait rien. Elle est le nom par lequel le CSS attrapera l'élément.

Analogie
Le code de couleur de tes cartables. L'étiquette rouge ne range rien toute seule : elle te permet de dire, une seule fois, « tous les rouges vont sur l'étagère du haut ». Sans étiquettes, tu devrais donner la consigne cartable par cartable.

C'est l'économie centrale du CSS. Les 61 accordéons de ton app ne portent pas 61 descriptions d'apparence : ils portent la même étiquette, et une seule règle les habille tous.

Classe ou id ?
Une classe est faite pour être partagée par beaucoup d'éléments. Un id est unique dans toute la page : c'est un nom propre. id="accordeon-acc-acp" désigne cet accordéon-là et aucun autre – c'est ainsi que le JavaScript le retrouve.

5. La règle CSS : sélecteur et déclarations

Voici la règle réelle qui habille toutes tes cartes (styles.css, l. 2142) :

.carte {
    background: var(--surface-carte, #1a3040);
    border: 1px solid rgba(106, 172, 184, 0.15);
    border-left: 3px solid var(--accent-primaire, #6aacb8);
    border-radius: var(--radius-grand);
    padding: var(--espacement-moyen);
}

Deux morceaux seulement :

  • Avant l'accolade, le sélecteur : .carte. Le point veut dire « la classe ». Donc : « tout ce qui porte l'étiquette carte ».
  • Entre les accolades, les déclarations, une par ligne, sur le modèle propriété: valeur;

Ça se lit à voix haute, et c'est comme ça qu'il faut le lire : « Pour tout ce qui porte l'étiquette carte : fond de cette couleur, bordure fine tout autour, bordure épaisse à gauche, coins arrondis, et de l'air à l'intérieur. »

Analogie
La consigne de correction appliquée à toute une pile de copies. Tu l'écris une fois, elle vaut pour chacune.

Le sélecteur qui se précise

.carte h3.carte-titre-bleu {
    background: var(--bleu-moyen);
    color: white;
    margin: -20px -20px 15px -20px;
    padding: 15px 20px;
}

Celui-ci (l. 2584) est plus bavard. Il se lit de droite à gauche : « un h3 qui porte l'étiquette carte-titre-bleu – mais seulement s'il se trouve à l'intérieur d'une carte ». C'est le bandeau bleu en haut de tes accordéons.

Le détail qui trahit
Les -20px en marge négative : le bandeau déborde volontairement de la carte pour venir coller ses bords. C'est le genre de chose que tu peux désormais repérer sans savoir l'écrire.

6. La cascade, et les variables de couleur

Voici la règle la plus instructive de tout le cours (l. 2245 et 2252) :

.carte.accordeon .accordeon-chevron {
    transition: transform 0.3s ease;
}

.carte.accordeon.ferme .accordeon-chevron {
    transform: rotate(-90deg);
}

Traduction : « le chevron d'un accordéon pivote d'un quart de tour si cet accordéon porte aussi l'étiquette ferme ».

Le CSS ne décide rien. Il dit seulement : si cette étiquette est là, alors ceci.

Qui pose et retire l'étiquette ferme quand tu cliques ? Le JavaScript. Voilà toute l'articulation des trois langages, dans quatre lignes : le HTML décrit, le CSS conditionne, le JavaScript décide. C'est la porte du Cours 4.

Pourquoi une seule modification change plusieurs écrans

Tu as sûrement remarqué var(--bleu-tres-pale) et var(--radius-grand). Ce sont des variables : un nom mis à la place d'une valeur. Elles sont définies une fois, en haut du fichier – et redéfinies selon le contexte :

--bleu-tres-pale: #142428;   /* l. 32   — mode sombre */
--bleu-tres-pale: #0c1820;   /* l. 401  — variante sombre */
--bleu-tres-pale: #f2f5f7;   /* l. 437  — mode clair */

Un seul nom, trois valeurs selon le mode. Tous les endroits qui écrivent var(--bleu-tres-pale) suivent automatiquement. C'est la réponse à ton vertige : tu n'as pas changé trois écrans, tu as changé une définition que trois écrans consultent.

L'autre face
Cette puissance est aussi le risque. Toucher une variable, c'est toucher tout ce qui s'en sert – y compris ce à quoi tu ne pensais pas. D'où la règle du projet : le travail visuel passe par design-system.html, qui montre d'un coup tout ce qui dépend de quoi.

7. Lecture guidée : l'extrait complet

Voici maintenant le vrai morceau, sans rien retirer (index.html, l. 8923 et suivantes). Lis-le une fois avant les annotations.

<div class="carte accordeon" id="accordeon-acc-acp">
    <div class="accordeon-header">
        <h3 class="carte-titre-bleu">
            <span class="accordeon-chevron">▼</span> Micro-données ACP
        </h3>
        <button class="option-accompagnement-guide-btn"
                data-action="ouvrirGuidePedagogique"
                data-param="acp" title="Guide ACP">
            <img src="icons/icon-book.svg" alt="" class="btn-inline-icon"> Guide
        </button>
    </div>
    <div class="accordeon-contenu">

        <!-- Checkbox d'activation principale -->
        <div class="form-group u-mb-15 u-p-12">
            <label class="u-align-center" data-tooltip="pref-outils-acp">
                <input type="checkbox" id="v2-pref-depistage-acp" checked
                       data-on-change="sauvegarderPreferencesV2">
                <strong>Activer la cueillette des données sur le contexte
                d'apprentissage et la performance</strong>
            </label>
            <small>Indices descriptifs Assiduité, Complétion et Performance.</small>
        </div>

Ce qu'il y a à voir

  • Deux boîtes sœurs dans la carte : l'en-tête (accordeon-header), toujours visible, et le contenu (accordeon-contenu), qui se replie. Le pliage n'est pas magique : ce sont deux zones distinctes depuis le départ.
  • Le bouton « Guide » est dans l'en-tête, pas dans le contenu : c'est pour ça qu'il reste accessible quand l'accordéon est fermé. Une décision d'interface, lisible dans la structure.
  • data-action="ouvrirGuidePedagogique" : le bouton ne contient pas le code qu'il déclenche. Il porte une étiquette qui nomme une intention ; ailleurs, un aiguilleur fait le lien. C'est la règle de sécurité « zéro handler inline » que tu as croisée au Cours 1 – et c'est encore le Cours 4 qui attend.
  • Le label qui enveloppe la case : parce que l'étiquette contient le champ, cliquer sur le texte coche la case. Rien d'autre n'est nécessaire pour ça.
  • checked : la cueillette A-C-P est activée par défaut. Une décision pédagogique, lisible en un mot dans le HTML.
  • Les classes u-mb-15, u-p-12 : des étiquettes utilitaires, « marge du bas de 15 », « rembourrage de 12 ». Quand une classe commence par u- dans ton app, c'est de l'espacement, jamais du sens.
Honnêteté
Dans le fichier réel, cet extrait contient aussi des style="..." écrits directement sur les balises. C'est l'exception qu'on essaie d'éviter : de l'habillage collé au squelette, qui échappe aux étiquettes et donc aux variables. Ça existe, ça marche, et ça se paie plus tard.

8. Révision

Réponds dans tes mots avant d'ouvrir.

1. Pourquoi dit-on qu'une page est un arbre ?
Parce que les éléments sont emboîtés les uns dans les autres, et que le retrait dit qui contient qui. Un élément appartient toujours à une boîte, et cette appartenance détermine où il s'affiche.
2. Que dit une balise, et que ne dit-elle pas ?
Elle dit ce que la chose est – un titre, un bouton, un champ. Elle ne dit rien de son apparence : ni couleur, ni taille, ni position. C'est le CSS qui s'en charge.
3. À quoi sert une classe, exactement ?
À rien par elle-même. C'est une étiquette, le nom par lequel le CSS attrape l'élément. Elle permet d'écrire une seule règle pour tous les éléments qui la portent.
4. Comment se lit une règle CSS à voix haute ?
« Pour tout ce qui correspond à ce sélecteur : telle propriété prend telle valeur, telle autre telle autre. » Le sélecteur désigne la cible, les déclarations disent quoi faire.
5. Pourquoi une seule modification peut-elle changer plusieurs écrans ?
Parce qu'une variable est un nom que consultent plusieurs endroits. Modifier --bleu-tres-pale, ce n'est pas modifier trois écrans : c'est modifier la définition que ces trois écrans vont chercher.
6. Le chevron pivote quand l'accordéon se ferme. Qui fait quoi ?
Le HTML décrit le chevron. Le CSS pose une condition : si l'élément porte l'étiquette ferme, alors pivoter. Le JavaScript décide, au clic, d'ajouter ou de retirer cette étiquette. Aucun des trois ne fait le travail des autres.
